# 🤖 Agno AI Agent v3.2 — Security & Stability

Многопользовательский AI-агент на **Agno + OpenRouter**: Telegram-бот, CLI с Rich Markdown, SQLite-история, отдельная LanceDB для каждого Telegram ID, RAG по PDF/DOCX/TXT/MD/CSV и изоляция загруженных документов в Docker.

**Репозиторий:** https://github.com/Dasgam/agno-ai-agent

> ⚠️ Важное: это усиленная изоляция, **не антивирус** и не гарантия отсутствия уязвимостей. Документы содержат недоверенные данные. Извлечённые фрагменты отправляются в OpenRouter при вопросах о документе. Не загружай секретные файлы, если это неприемлемо.

## Что нового в v3.2

- **Отдельный временный Docker-контейнер на каждый документ** вместо общего постоянно работающего worker. Применяются `--network none`, `--read-only`, non-root, запрет capabilities, ограничения RAM/CPU/PID, тайм-аут и одноразовые каталоги ввода/вывода.
- Устранён ложный отказ на обычные вопросы со словом «файл» («Как создать файл в Python?»).
- `/delete 1` и `/clearfiles CONFIRM`: удаляют записи из активного RAG-индекса, каталога файлов и сохранённый текст. Операции ограничены владельцем документа. Фрагменты загруженных документов **не записываются в SQLite-память Agno**, чтобы удаление не оставляло копию в истории диалога.
- Срок хранения документов: **30 дней** по умолчанию (`DOCUMENT_RETENTION_DAYS`), проверяется при запуске и далее раз в час; `0` отключает автоматическое удаление.
- Улучшен выбор выдержек из длинного PDF: для общего обзора используются фрагменты из начала, середины и конца, для конкретного вопроса — наиболее релевантные фрагменты.
- Markdown в Telegram преобразуется в безопасный HTML; в CLI отображается через Rich. Если длинный ответ обрезан, бот сообщает об этом.
- Дополнительные автоматические тесты изоляции, удаления чужих файлов, тайм-аутов Docker и работы парсера.

## 1. Обновление существующего проекта на Windows

**Сначала останови** Telegram-бот (`Ctrl+C`) и старый Docker-worker. Открой терминал **CMD** в корне папки проекта `agent+tg`.

Сделай резервную копию папки `agent/data/` и файла `agent/.env`. Затем перенеси файлы ZIP в корень проекта **с заменой**. Существующие `agent/.env` и `agent/data/` не удаляй. После переноса можно удалить устаревший `worker/worker.py` — он больше не используется.

Останови старый общий worker (если запускался в v3.1):

```cmd
docker compose down --remove-orphans
```

Активация виртуального окружения, если оно ещё не активировано:

```cmd
.venv\Scripts\activate.bat
```

Если `.venv` нет, создай на **Python 3.12**:

```cmd
py -3.12 -m venv .venv
.venv\Scripts\activate.bat
```

Установи зависимости:

```cmd
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## 2. Настройка `.env`

Твой реальный файл находится по пути `agent/.env` и **никогда не должен публиковаться в GitHub**. Если файла нет, скопируй пример:

```cmd
copy agent\.env.example agent\.env
```

Пример без реальных ключей:

```env
OPENROUTER_API_KEY=your_openrouter_api_key
ID_MODEL=nvidia/nemotron-3.5-lightning:free
TELEGRAM_BOT_TOKEN=your_new_telegram_bot_token
TELEGRAM_OWNER_ID=111111111,222222222,333333333
DOCUMENT_RETENTION_DAYS=30
```

В `TELEGRAM_OWNER_ID` можно перечислить сколько угодно разрешённых Telegram ID через запятую. Твой старый Telegram-токен ранее появлялся в логах — **отзови его у @BotFather и используй новый**.

## 3. Docker: сборка образа безопасного парсера

Запусти **Docker Desktop** в режиме **Linux containers**, затем из корня проекта:

```cmd
python agent\prepare_sandbox.py
docker compose build document-sandbox
docker image inspect agno-document-sandbox:3.2
```

**Важно:** в v3.2 **НЕ надо** выполнять `docker compose up -d document-sandbox`. Фоновый worker больше не используется. Telegram-бот сам создаёт отдельный `docker run --rm` для каждого загруженного файла. Контейнеры не имеют доступа к сети или другим пользовательским документам.

Если нет доступа к Docker или образ не собран, загрузка файлов отключается; бот не обходит sandbox.

## 4. Запуск Telegram-бота и CLI

Запустить Telegram-бота:

```cmd
python agent\telegram_bot.py
```

CLI в другом терминале (необязательно):

```cmd
.venv\Scripts\activate.bat
python agent\agent_cli.py
```

**Не запускай две копии Telegram-бота с одним токеном.** Бот работает через long polling, пока процесс запущен. Домен и веб-сервер не требуются.

### Команды Telegram

| Команда | Назначение |
|---|---|
| `/start`, `/help` | Запуск и помощь |
| `/myid` | Telegram ID (даже если доступ не предоставлен) |
| `/models`, `/model 9` | Список моделей и смена модели |
| `/new` | Новый диалог, сброс активного документа |
| `/status` | Модель, сессия и активный документ |
| `/files` | Список собственных документов |
| `/use 1` | Выбрать документ для вопросов |
| `/delete 1` | Удалить документ №1, его активный индекс и текст |
| `/clearfiles CONFIRM` | Удалить все собственные документы |

Отправь PDF/DOCX/TXT/MD/CSV как обычный файл в личный чат. После успешного разбора спроси: **«О чём этот PDF?»**. Можно переключиться на другой документ через `/use 2`.

Лимиты: до 8 МБ на файл, максимум 120 страниц PDF и 250 000 символов извлечённого текста, до 20 документов в личной библиотеке, 10 загрузок и 60 текстовых запросов в день на человека (UTC). Для сканов без текстового слоя нужен OCR — здесь он намеренно не добавлен.

## 5. Проверки перед GitHub

```cmd
python -m compileall -q agent worker
python -m pip install pytest
python -m pytest -q tests
```

Все проверки должны пройти локально. GitHub Actions автоматически повторит тесты при push. **Успешные тесты не означают, что Docker и Telegram полностью проверены:** дополнительно отправь небольшой PDF и проверь `/delete 1`.

## 6. Публикация на GitHub

```cmd
git status
git add .
git commit -m "Update agent to v3.2"
git push origin main
```

`.env`, `agent/data/`, виртуальное окружение, логи и пользовательские документы исключены через `.gitignore`. Проверь `git status` перед отправкой и **не публикуй токены, их значения, дампы БД и логи Telegram API**.

## Обновление и совместимость

- Существующая SQLite-история, настройки пользователей и персональные RAG-индексы **не удаляются при обновлении**.
- Загруженные документы v3.1 в папке `agent/data/telegram_extracted_text/` остаются доступными через `/files`.
- Старый фоновой Docker-worker можно остановить и удалить. Папка `agent/data/sandbox_spool/outbox/` от v3.1 больше не используется; проверь и очищай только после резервной копии и остановки старого worker.
- **Важно для пользователей v3.1:** прошлые запросы с фрагментами PDF могли сохраниться в `agent/data/sessions.sqlite3`. v3.2 не удаляет эти старые записи автоматически. Если нужно убрать прежние фрагменты, после резервного копирования и остановки бота удали старую `sessions.sqlite3` вместе с её `-wal` и `-shm` (при наличии). Это также удалит всю прежнюю историю диалогов Agno.
- Физическое уничтожение данных в старых версиях LanceDB, снапшотах, резервных копиях или на SSD не гарантируется командой `/delete`: она удаляет активные записи поиска и сохранённый текст.
- Выдержки из длинного документа **не равны полному документу**: агент получает выбранные фрагменты. Полный анализ всех страниц потребует отдельного многоэтапного пайплайна.
- Вопросы по активному PDF обрабатываются без постоянной памяти Agno, чтобы извлечённый текст не оставался в истории после удаления. Для уточняющего вопроса укажи тему самостоятельно. Обычный чат без документа продолжает сохраняться в SQLite.

## Типичные ошибки

| Ошибка | Решение |
|---|---|
| `docker is not recognized` | Установи Docker Desktop, перезапусти CMD |
| `Docker image ... not found` | `docker compose build document-sandbox` |
| `Permission denied` для `/output` | Проверь права общей папки Docker Desktop на Windows; на Linux — UID/GID хоста |
| `Timed out` при PDF | Попробуй меньший файл, проверь `docker ps -a`; один файл ограничен по времени |
| `No module named ...` | Проверь `.venv` и `python -m pip install -r requirements.txt` |
| `/delete` сообщает об ошибке индекса | Не удаляй базу вручную; проверь `agent/data/telegram_bot.log` и повтори |
| Бот не отвечает из другого аккаунта | Добавь Telegram ID в `agent/.env`, перезапусти бота |
| Старый конфликт `getUpdates` | Останови вторую копию бота |
| OneDrive мешает Docker bind mounts | Перемести проект в обычную локальную папку, например `C:\Projects\agno-ai-agent` |
